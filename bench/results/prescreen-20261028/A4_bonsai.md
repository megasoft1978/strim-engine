# A4: Ternary-Bonsai-2-27B-mlx-2bit paper check (HF card + config.json, 2026-10-28)
- Format: affine 2-bit, group_size 128 ("quantization": bits 2, group_size 128, mode affine) holding ternary {-1,0,+1}: codes {0,1,2} decode with scale s, bias -s. 2.25 bits/weight effective with scale+bias. Disk 8.60 GB (7.67 LM + 0.92 vision tower fp16). Our affine qmm path (bits=2, gs=128) loads the weights as-is via QuantConfig.
- Rotation: model_type prism_hadamard_qwen35; blockwise orthogonal Hadamard, block 1024, fixed +-1 signs, folded into the stored weights offline; runtime must apply the matching transform to ACTIVATIONS at every rotated projection input and use an inverse-rotated embedding lookup (embed/lm_head are in the module list with "block": 1024, dtype float16). Stock loaders skip this and "return wrong output rather than an error". The card says the metadata is declared in the file; loader bundled in the repo runtime/ dir (Python, mlx-vlm based).
- Loader delta vs ours: (1) parse the rotation metadata (per-module block size + sign vector), (2) apply x -> H_1024-blockwise(x * signs) before each rotated qmm (MLX has hadamard_transform in core; size 1024 is a power of two so a single op per projection, memory-bound ~ one extra read/write of the activation), (3) inverse rotation on the embedding rows (one-time at load or per lookup), (4) config key mapping (text_config, 64 layers, full_attention_interval 4: same topology as Qwen3.8-27B: 48 linear + 16 full attention).
- MTP: NONE (mtp_num_hidden_layers 0, components.mtp false). Our MTP head (qwen38-mtp-4bit) was trained against the unrotated Qwen3.8 hidden state; Bonsai is a re-trained/distilled ternary model, so grafting is not a drop-in: its hidden states differ (rotated basis in the folded weights is internal, but the model itself was QAT'd). Needs a measured acceptance test; expect low acceptance, so assume plain decode: roofline 530 GB/s / ~7.7 GB = ~69 tok/s upper bound, i.e. about parity with current 4-bit + MTP (72 tok/s at 4K). The value is the 16 GB RAM tier (8.6 GB weights), not speed.

- First spike step (half a day): `strim benchprescreen`-style microbench, no engine change: read the safetensors header + config modules for the per-module rotation metadata; build a one-layer reference: take layer 0 linear_attn.in_proj_qkv (2-bit gs128) and verify that qmm(hadamard_blockwise(x*signs), W) matches the card's python runtime output for a fixed x (dump from the card's runtime on any machine) to <1e-2; time qmm 2-bit g128 at M=1/3/1024 for the real shapes plus the hadamard op. If the rotated qmm is not >=1.6x faster than 4-bit qmm at M=1 (memory-bound expectation ~2x) or rotation overhead per pass exceeds ~3 ms (64 layers x ~3-4 projections), stop.
