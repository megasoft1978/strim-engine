# Strim / Qwen3.8-27B 4-bit harness failure mining (2026-10-30)

## Evidence and limits

Primary evidence is the verified thinking A/B capture `bench/results/align-thinking-20261029/raw/{off,on}`: 24 ledger rows per arm, 21 paired valid tasks after exclusions, plus its saved event streams and `analysis.json`. Traces live under `raw/off/jobs` and `raw/on/jobs`; job IDs below map through `job.json.cwd`. This is a small, task-mixed sample, not a stable estimate of general pass rate. Three OFF rows were excluded from the paired analysis (hd-rx-02, hd2-rx-01, rx-01); ON excluded hd-rx-02. Several verification notes expose a runner permission failure reading `/runs/`, so those failures are not attributed to the model. A snapshot of the separate live `/tmp/ev1/run2` traces, ledger, and live prompt/knobs was copied first to `/tmp/fm1/data/run2`; its 30 ledger rows are not combined with A/B because they include candidate/run phases and incomplete coverage.

### Failure modes, repeated work, and examples

- **Wrong/incomplete fix then limit, OFF (8/24 ledger rows):** `hd-js-01`, `hd-rx-02`, `hd2-js-01`, `hd2-rx-01`, `rb-01`, `rb-03`, `rx-01`, `tf-02` ended with `harness_status=limit`, `claimed_done=false`. Excerpts include unresolved assertions (e.g. rb-01 expected `11th`, got `11st`; rb-03 retained 2 failures/6 errors; tf-02 retained a Go byte-format mismatch). These are real unsuccessful patches, distinct from false completion. Example jobs: OFF `j_tazvvs6bux` (rb-03), `j_qxkb3qemmc` (tf-02).
- **Long unresolved loops, ON (3/24):** hd-rx-02 (`j_2dba6dj6be`), hd2-js-01 (`j_n36lzem7tl`), tf-02 (`j_osrwijwqye`) reached ~900s and ended `limit`, no false-done. hd-rx-02 verifier reports `PermissionDenied` opening a temporary `/runs/` directory; tf-02 retains the same 1000 kB vs 1 MB mismatch seen OFF. This is evidence for earlier stopping on stalled loops, not evidence that thinking harms solution quality.
- **Thinking contrast:** paired outcomes were both-pass 16, ON-only 3, OFF-only 0, both-fail 2. OFF-only failures became passes ON include representative `rb-01`, `rb-03`, and `rx-01`; the two ON-only failures still had genuine failing tests/verification. Thus all-turn thinking plausibly helped hard reasoning, but the 3.3x paired wall cost makes it a poor default. A first-planning-turn experiment is explicitly supported by `docs/EVOLVE.md`, but this A/B does not test it.
- **First three turns:** traces show successful solutions often inspect task/tests and implementation before editing; e.g. ON `j_qrh4lnr5do` turn 1 lists repo, reads target test, turn 2 lists source tree/reads source, turn 3 continues targeted inspection, then states a concrete API plan before edit. Failed traces include early test attempts before locating enough context and then broad reruns; however no saved aggregate classifies all first-three-turn sequences by outcome, so this is a trace example, not a measured predictive rule. A proper paired first-3-turn analysis is required before claiming causality.
- **Repeated identical calls / rereads:** OFF has 113 edit calls versus 47 ON, alongside 213 vs 83 bash calls. In OFF `rb-03` (`j_tazvvs6bux`), repeated Ruby test outputs cycle from 6 errors to 4 then 3/2 failures; this is iterative but has no clear convergent verification checkpoint. The available saved aggregate does not count identical argument hashes or same-file rereads, so no fabricated repetition rate is reported. The run-time guard already aborts after max-repeated calls and five consecutive errors (`docs/AGENT-DESIGN-RESEARCH.md`).
- **Tool-call validity and args:** observed errors are mostly legitimate nonzero tests or `ToolchainGuard` refusals, not malformed function envelopes. Examples include OFF bash refusal of `bun` without `bun test` and a failing Node test in OFF traces. ON has one TypeScript compile error and one sandbox refusal (`/tmp/out.txt: Operation not permitted`). There is no observed evidence in these A/B summaries of `edit_file` uniqueness/not-found errors, JSON escaping failures, or line-number arguments (edit schema is exact-text `old`/`new`, not line-number based). Therefore auto-repair of source edits or shell commands is not justified. Parser code already refuses truncated XML without executing it (`Sources/StrimTemplate/ToolCallParser.swift`); malformed OFF event lines are capture parsing anomalies, not proof of model parser defects.

### Prompt/context cost

Shipped `system.md` is 3,492 bytes and `tool_guidance.md` 864 bytes (4,356 bytes total; rough text-only estimate ~1.1k tokens at 4 bytes/token, not tokenizer-measured). Seven tool schemas are rendered separately by `ToolCatalog`; a precise schema token count is not recorded in these traces. The repository's earlier `docs/PLAN-AGENT-HARNESS-2026-10-26.md` estimates ~1.3k tokens for a four-tool delegation surface, which must not be mistaken for the seven native tools. Per-row accumulated prompt counts (39.7k OFF, 64.8k ON) include prior conversation/replay and cached prefix usage, so do not isolate static prompt/schema cost from these totals. ON generated 174,872 completion tokens across its 24 rows vs OFF 48,278 across 24 rows in `analysis.json`; ON's 4 compactions vs 1 OFF are consistent with larger reasoning/history load. Tool result text volume fell 30% ON despite higher prompt usage, so generated reasoning, rather than larger tool outputs, is the likely measured cost driver.

## Ranked proposals

Effects below are hypotheses, not measured gains. Validate on paired held-out tasks and report pass, wall, completion tokens, false-done, and timeout separately.

1. **Default to `first_planning_turn`, not `all_turns_medium`.** Exact knob: `thinking: "first_planning_turn"` in pack `knobs.json` / `PackCandidate.thinking` (`docs/EVOLVE.md`). Failure targeted: hard-task reasoning misses seen in 5 additional paired passes, while avoiding repeated hidden reasoning. Expected pass effect: likely retain some of the 3 ON-only gains; unknown. Expected turns: likely similar (paired turn count ~8-9 either way); wall/completion should fall substantially from ON's 271s/4,524 completion tokens toward OFF's 85s/801, but that magnitude is unmeasured. Risk: later-step reasoning may be required; all-turn thinking contributed to hard-task fixes. Validate `evolve` coordinate `thinking` with OFF, first-planning, and all-turn arms on same 21-task subset, 2 reps, paired.
2. **Use a stop-and-diagnose rule after repeated unchanged test failures.** Exact system/tool guidance addition: “After a test command fails, identify the failing assertion/error and the smallest relevant source/test context; make one targeted change. Do not rerun the same full suite without a source change. If the same failure remains after two edits, inspect the exact failing path and report the blocker; do not repeat the command.” Failure targeted: unresolved 900s ON limits and OFF edit/bash cycles (OFF 213 bash + 113 edit calls; ON 3 limits; example rb-03 repeated full-suite failures). Expected pass: uncertain, could preserve a correct partial patch and avoid exhausting budget; expected turns/wall: lower on stalled tasks. Risk: some suites are cheap or failures require iterative tests; blanket skip can hide regressions. Validate via `tool_guidance` evolve coordinate and annotate repeated-test cycles / pass rate, with no limit changes.
3. **Add concise test-first and targeted-rerun guidance to bash schema description.** Exact location `Sources/StrimHarness/BashTool.swift`, `ToolSpec` description: recommend identify the repository's documented test command and run the narrow relevant test first; run full suite once after focused tests pass; do not pipe away exit status or truncate away the failing assertion. Failure targeted: full/noisy tests and losing diagnostic evidence in captured result excerpts; test-fix failures remain 8 OFF limits and 3 ON limits. Expected pass: modest/unknown; expected wall and tool output: lower when narrow tests are available. Risk: task may only be verifiable via full suite; test commands can be guarded. Validate as a v2 schema candidate on task-fix tasks, recording command count, exit statuses, output chars, and pass.
4. **Preserve task-specific command failure excerpts in the result shaper.** Exact location `Sources/StrimHarness/AgentLoop.swift` result-cap shaping / `HarnessKnobs.resultCapChars` (EVOLVE `result_cap` currently caps head+tail 1,500/8,000 chars). Ensure test outputs retain first error plus last summary and explicit exit code; cap repetitive middle logs. Failure targeted: long test outputs may obscure key assertion/stack context; 21 OFF and 18 ON tool results exceeded 4k chars, while average result was ~950 chars. Expected pass: small potential improvement on repair decisions; modest output/prompt reduction, hence lower prefill/wall. Risk: relevant middle diagnostics could be dropped; existing head/tail can already preserve useful edges. Validate `result_cap=tight` plus synthetic failing output unit cases and paired evolve tasks; don't globally reduce blindly.
5. **Safe parser auto-repair only for deterministic outer-envelope defects, not arguments.** `Sources/StrimTemplate/ToolCallParser.swift` currently tolerates a missing `</function>` before `</tool_call>` and refuses truncated calls. Add unit-testable recovery only for a complete, uniquely delimited call with missing function close; do not alter `path`, edit `old/new`, shell command, or JSON string values. Evidence: 7 malformed OFF event lines, 0 ON, but not correlated to executed tool calls, and no observed argument-shape error rate. Expected pass/wall effect: currently unquantified and likely small; can prevent one recoverable lost call. Risk: accidental execution of malformed/ambiguous output. Validate parser fixtures: recovery for one unambiguous missing close; rejection for truncation, duplicate functions, ambiguous nesting, invalid JSON/non-string types. This ranks last because trace evidence is weak.

Not recommended from this sample: automatically rewrite edit arguments or retry arbitrary bash errors; neither has concrete frequency evidence, and silent correction could change task intent. Do not loosen turn/time ceilings based on this data: ON's 900s limits indicate a stopping problem, not proof that more budget would pass.
