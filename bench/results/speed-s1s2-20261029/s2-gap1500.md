# S2: STRIM_PREFILL_GAP_MS 1500 vs default 3000 (2026-10-29)

Setup: strim serve (MTP head), qwen38-4bit, greedy, 128 new tokens, barrier-started concurrent W6 groups, mixed cold prompts (916 / 882 / 1890 / 2060 / 3342 / 3345 / 6736 / 14096 tokens; c=4 uses the first four: 6736, 916, 3345, 1890; c=8 all eight). 4 reps x 2 servers per arm, order ABBA (A=3000, B=1500). c=1: three single prompts (916, 3342 and 14096 tokens), 3 reps x 2 servers. Machine shared: load average 3.6 to 26 during runs (other sessions), so absolute numbers are slow; arms are compared interleaved. Per-request TTFT pooled over both servers.

| group | arm | n req | TTFT p50 s | TTFT p95 s | TTFT mean s | agg tok/s (mean of groups) | decode tok/s (median req) |
|---|---|---:|---:|---:|---:|---:|---:|
| agent-c8 | gap 3000 | 64 | 9.06 | 35.76 | 12.09 | 22.23 | 3.43 |
| agent-c8 | gap 1500 | 64 | 9.6 | 44.53 | 13.11 | 22.03 | 3.97 |
| agent-c4 | gap 3000 | 32 | 6.47 | 13.88 | 6.41 | 27.03 | 10.08 |
| agent-c4 | gap 1500 | 32 | 4.64 | 14.49 | 6.38 | 26.38 | 8.57 |
| agent-c1 | gap 3000 | 18 | 3.38 | 13.59 | 5.99 | 26.68 | 71.01 |
| agent-c1 | gap 1500 | 18 | 3.45 | 14.55 | 6.12 | 26.18 | 65.94 |

c=8 sorted-TTFT [min, ~median, max] per server: A1 [1.0,4.1,37.5]  B1 [1.0,4.1,44.5]  B2 [1.0,4.2,45.3]  A2 [1.0,4.3,38.5]. The slowest request (14K-token prompt) is delayed 7 s more with gap 1500 in both B runs and both A runs agree: not noise.

Keep rule (c=4/8 p95 TTFT improves >=5%; c=1 TTFT and aggregate regress <=1%): c=8 p95 +24.5% (worse), c=4 p95 +4.4% (worse), aggregate tok/s -2.4% (c=4) / -0.9% (c=8), c=1 aggregate -1.9%. FAIL -> default stays 3000 ms, no code change.
Why: a shorter cap forces more decode units into the long request's prefill; decoders of already-prefilled short requests gain inter-token latency but the p95 request is the long prefill, which loses. Plan estimate of -6..-11% is not reproduced on a mixed-length load.
Note: c=1 has no concurrent decoder, so the gap rule cannot act; its differences (TTFT p95 +7%, decode 71 vs 66 tok/s) are the noise floor of this shared machine, which also bounds any small effect above.

Bit-identity (scheduling only): greedy, 160 new tokens, same prompts, fresh server per arm; sha256 of the 16 outputs (4 serial, 4 concurrent c=4, 8 concurrent c=8) are identical for gap 3000 and gap 1500 (raw/ident/g3000|g1500/hashes.txt, diff empty).
