## What we do with them

**Phase A — speed (this week).** Run 6-bit, 5-bit, 4-bit and each MTP overlay at 4k/16k, same prompt,
same harness. Gate: 6-bit + MTP ≥ 38 tok/s @4k; 5-bit + MTP ≥ 45; 4-bit + MTP ≥ 55. Verify that the
8-bit MTP drafter is accepted by the 6-bit target (it should be — the drafter is independent).

**Phase B — quality (this week).** The three-task suite in
[TASKS-2026-10-25.md](TASKS-2026-10-25.md), same prompts and step limits, on 8-bit, 6-bit, 4-bit and
oQ4e if it is reachable. Gate: 6-bit ≥ 8-bit − 1 task; 4-bit only if it holds the same line.

**Phase C — long context.** 64k with int8 KV on the winning quant; peak ≤ 52 GB, no swap growth.

**Phase D — GGUF (only if needed).** GSQ-IQ3_S via llama.cpp, to test whether a 3.5 bpw GGUF really
holds coding quality. This is a different engine, so it is a reference point, not the product path.

## Notes

- The MTP drafter is quantized separately from the target. An 8-bit drafter works with a 6-bit target;
  acceptance may differ slightly, so it is measured, not assumed.
- `jundot/*` repos returned HTTP 307 to the API request; confirm they are public and downloadable
  before scheduling a 17 GB pull.
- Nothing below ~12 GB is worth testing for agentic coding: the independent sweeps put the quality
  cliff at ~7–8 GB and the collapse at ~6 GB.
