# Engine MLX memory breakdown (2026-10-26)

Machine: Apple M5 Max, 64 GB. Model: qwen38-4bit + qwen38-mtp-4bit. Branch mem-wave3.
Units: MiB unless marked GB (Swift stats print decimal GB). Raw logs: `bench/results/mem-20261026/`.

## Summary

- The engine's memory is dominated by **prefix-trie nodes that cost ~1.18 GiB each in real memory but are accounted at 215 MiB**. A 4 GiB trie budget therefore means ~23 GiB of real memory, not 4 GiB.
- Cause: each trie node holds the GDN conv state as a view into the whole 1027-token `convIn` buffer (`Sources/StrimCore/GDN.swift:273`). That retains 48 layers x 21 MB = ~963 MiB per node. The node's accounting counts only the 61 KB logical conv state.
- A second bug inflates the process further: `Node.parent` is a strong reference, so dropping a `PrefixStore` (what `resetPrefixCache` does) leaks the whole trie through a retain cycle. Active memory did not fall when the trie was dropped in the full run (see (g) and the leak section below).
- MLX buffer cache plateaus at its 4 GiB limit (not a leak, but +2-4 GiB on top of active).
- Transient per 1024-token prefill chunk is ~0.8 GiB (constant for 1K-4K positions).

## Method

- API used (from `.build/checkouts/mlx-swift/Source/MLX/Memory.swift`): `Memory.activeMemory`, `Memory.cacheMemory`, `Memory.peakMemory` (getter; setter resets the peak counter, its value is ignored), `Memory.cacheLimit`, `Memory.memoryLimit`, `Memory.clearCache()`, `Memory.snapshot()`.
- Instrumentation (`Sources/StrimEngine/EngineCore.swift`, off by default):
  - `STRIM_MEM_TRACE=1`: one `[mem]` stderr line after weight open, after warm, and after every work unit (prefill chunk or decode pass). The line carries active, unit peak, run peak, cache, trie bytes/nodes, hot sessions, admitted bytes. The peak is reset at each unit start, so `peak` is that unit's transient high-water mark.
  - `STRIM_MEM_CLEAR=1` (only with trace): `Memory.clearCache()` after every unit (experiment (g)).
  - Cost when off: one static Bool check per unit.
- Caveat: in trace runs `mlxPeakBytes` in the stats line is the last unit's peak. Use `runPeak` in the trace.
- Config: default `EngineConfig` (budget 80% of RAM = 55 GB, prefix trie 4096 MiB, MLX cache limit 4096 MiB).

## Leak: trie not freed on store drop

Full run (`r7`, unit 313 -> 325): `resetPrefixCache` replaces `PrefixStore`. Accounted trie fell 3,437 -> 214 MiB but active rose 42,218 -> 42,564 MiB. Expected drop: ~18 GiB. Similar at unit 385 -> 397 (trie 2,577 -> 214; active 55,961 -> 56,727).

Cause (inferred from code, not yet confirmed with a deinit counter): `Node.parent` and `parent.children` are both strong references, so each root/child pair is a retain cycle. Dropping the store leaks the chain.

Effect in the full run: active stays at 42-57 GiB across scenarios with a near-empty trie. Peak 66,020 MiB at unit 530 with trie 1,718 MiB accounted. Stats print 69.2 GB for the last unit peak. This reproduces the brief's 43-69 GB.

Production (`strim serve`) never resets the store, so the leak is a bench-process problem unless the server calls reset. Still a leak.

## Admission: corrected formula (proposal; not applied)

All MiB. Constants measured or exact from config (16 full-attn layers, 48 GDN layers, Hv=48, Dk=Dv=128, kv heads 4, head dim 256).

- Fixed: `W` (weights active, ~0.95 x file bytes, ~14,800 measured) + `P` (prefix budget, valid only once accounting is honest) + `C` (MLX cache limit) + `T` (one prefill-chunk transient, ~800, reserved once).
- Per request: `tokens x 64 KiB` (KV) + `tokens x 4 KiB` if MTP (head KV) + `144` (GDN ssm) + `3` (conv, owned copy). Until the conv view is fixed, add `963` while the request is between its last prefill chunk and its first decode step.
- Per trie node (honest): `64 (KV) + 4 (MTP) + 144 (GDN) + 3 (conv)` = 215. Currently accounted as 215 but real ~1,175.
- Current `Admission.decide` uses `fixed = weights + prefixCacheBytes`, which is only safe with honest accounting. It does not include the MLX cache limit or the real trie cost.

## Trie storage: every-Nth GDN boundary (evaluation, not implemented)

Per 1024-token block (MiB): KV 64 + MTP 4 always stored; GDN 144 (+3 conv) only every N-th boundary. Hits snap back to the nearest stored GDN boundary and recompute up to N-1 blocks (exact, same chunk alignment as a miss). Requires lookup/restore changes in `PrefixCache.swift`.

| N | Avg accounted / block | Blocks in 4096 MiB | Tokens cached | 40K-token session full trie | Worst-hit recompute (~1.0 s/block) |
|---|---|---|---|---|---|
| 1 (now) | 215 | 19 | 19,456 | 8.39 GiB (stalls at 19 nodes) | 0 |
| 2 | 141 | 28 | 28,672 | 5.52 GiB | 1 block |
| 4 | 105 | 39 | 39,936 | 4.09 GiB | 3 blocks (~3 s) |
| 8 | 86 | 47 | 48,128 | 3.37 GiB | 7 blocks (~7 s) |

KV alone for 40K tokens is 2.5 GiB. The 40 GDN boundaries at N=1 are 5.6 GiB, which is why the trie stalls at 19456.

Caveat: the every-N saving applies to the accounted cost. It only becomes a real saving once the conv view retention is also fixed (conv base is ~963 per node in real memory, versus 144 for GDN ssm).

## Recommendations

1. STRIM_MEM_BUDGET_GB on 64 GB: set **32** now (default 55 GB = 80% of RAM is too high, and admission cannot see the real trie cost). After the conv-view and leak fixes, **24** is enough: 14.8 weights + 4 trie + 4 cache + ~0.8 transient + ~1 GiB per two live 4K requests.
2. Until the trie accounting is fixed, cap the trie with `STRIM_PREFIX_CACHE_MB=1024` (about 4 nodes, ~4.7 GiB real). At the default 4096 MiB the real trie reaches ~22 GiB, which is the largest single term and the source of the swap.
3. MLX cache: `mlxCacheLimitBytes` default 4 GiB costs ~3.5 GiB of steady memory. 512 MiB saves that but costs 3-6% single-stream decode. Not applied. Suggest 1 GiB as a compromise (not measured).
4. Patch proposals (not applied; outside owned files):
   - P1 `Sources/StrimCore/GDN.swift:273`: store an owned copy of the conv state (`state.conv = <copy of convIn[..., n-3 ..< n]>`). Check that `contiguous()` actually copies a B=1 slice; if it returns the view, use an explicit copy. Expected: -963 MiB per trie node and per in-flight request. This does not change arithmetic.
   - P2 `Sources/StrimCore/PrefixCache.swift` `Node.parent`: make it `weak`. Expected: the store drop frees the trie (about -18 GiB after a full trie reset in the bench). Ancestors stay alive via `children` from the root.
   - P3 Trie accounting: once P1 is applied, `node.bytes` is honest (~215). Until then, account the real base size.
   - P4 Every-N GDN storage (design above).
5. Re-run gen16 after any of the above: `bench/results/ab-20261026-131238/gen16-swift.txt` ids, checked this session (MATCH with instrumentation on the build; instrumentation off by default).
