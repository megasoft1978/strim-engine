01 / Local inference, Apple silicon

Run a 27B model on your Mac like it is a server.

Strim is one Swift binary that runs Qwen3.8-27B. A local backend for Claude Code and Codex.

03 / The wide field

Eight engines, one tower.

Decode speed, tokens per second, Qwen3.8-27B 4-bit, W1 greedy-256, Apple M5 Max 64 GB, all 8 engines, run of 2026-10-26. Strim's later build (2026-10-28) is faster still: 70.7 tok/s at 4K context.

04 / Ratios, today

Where Strim stands, honestly.

vs rapid-mlxvs mlx-vlmRight of the line = Strim faster

Where it is not faster. Cold 32K prefill is 0.96x of rapid-mlx and 0.95x of mlx-vlm, and 8-agent throughput is 0.94x of mlx-vlm. Prefill-bound work is a tie or a small loss; the gains are in decode and cache reuse.

05 / Proof

Three numbers to remember.

1.5x

faster decode

70.7 tok/s at 4K context, against 47.7 for rapid-mlx and 30.7 for mlx-vlm. Still 1.5x at 32K.

2.8x

agents sharing a prefix

Four clients on one 16K prompt prefix: the cache is reused instead of recomputed.

1.7x

faster first token

Median time to first token at 8 concurrent agent requests, about 40% lower.

06 / Install

Three commands.

  1. Install

    brew install megasoft1978/strim/strim

    Homebrew first. The curl script does the same.

  2. Pull the model

    strim pull

    Pinned revision, resumable, verified.

  3. Serve

    strim serve

    Point Claude Code or Codex at the local port.

07 / FAQ

Questions.

Which model does it run?

Qwen3.8-27B in 4-bit, with the MTP head, on Apple silicon.

Which clients work?

Claude Code and Codex are the targets: Strim is a local backend that behaves like a server.

How were the numbers measured?

Apple M5 Max, 64 GB, same prompts for every engine, one engine on the GPU at a time. Raw files are in bench/results.
