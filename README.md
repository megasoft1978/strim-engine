# Strim

A Swift-only inference engine and local server for one model: **Qwen3.8-27B (dense), 4-bit affine g64 with its MTP (multi-token-prediction) speculative head, on Apple Silicon.** One process and one binary, no interpreter or other runtime. One loopback port speaks OpenAI Chat Completions, OpenAI Responses and Anthropic Messages, so Claude Code and Codex can use it as a local backend; an MCP endpoint lets them delegate bounded tasks to the local model. Tested only on a 64 GB M5 Max.

Public repository, MIT license. Full results, methods and caveats: [site/index.html](site/index.html) (static, works offline). Every number below is a figure in [site/data/results.json](site/data/results.json) with its source file; this README is generated by `strim site build`.

## What the data supports

Final head-to-head, 2026-10-28: Strim (build 2df65e7) vs rapid-mlx 0.15.7 (MTP on) vs mlx-vlm 0.7.10, Qwen3.8-27B 4-bit, 64 GB M5 Max, 2 passes, one rep each.

- Strim decodes **24-41% faster than rapid-mlx** and **1.9-2.3x faster than mlx-vlm** at 4K to 32K context.
- With four agents sharing a 16K prefix, aggregate throughput is **2.7-2.9x faster** than either rival.
- Median first-token latency is **21-44% lower** at 4 to 8 concurrent requests.
- It **ties rapid-mlx** on the 8-turn agent replay (49.69 s vs 49.45 s) and on cold 4K prefill.

Where Strim is **not** faster:

- Cold prefill is 2-3% slower at 16K and 32K.
- Aggregate throughput at c=4 and c=8 is 4-14% lower than the best rival.
- p95 first-token latency at 512-token concurrency is 22-31% worse.

Bold = best of the three. WIN / LOSS = outside a 2% band, TIE = within it. The full 33-cell table with ratios is on the [site](site/index.html#r-final).

### Quality wording

- **Exact within one fixed chunking policy:** a prefix-cache hit equals a miss bitwise, because prefill always runs in aligned chunks.
- **Not bitwise elsewhere:** batched decode and the cache cuts can change near-tie tokens. Greedy output over 8 prompts and 64 tokens: Strim vs itself 8/8 identical, vs rapid-mlx 7/8, vs mlx-vlm 6/8.
- Multi-step agent quality has been checked only on the corpora described under [Agents](#agent-harness-and-mcp); see [Not yet validated](#not-yet-validated).

## Install and quickstart

```sh
swift build -c release --disable-sandbox
.build/release/strim serve models/qwen38-4bit models/qwen38-mtp-4bit --port 8203
```

Weights are not in the repository. Fetch the 4-bit checkpoint and the MTP head into `models/` with `aria2c -x 4 -s 4 -k 1M -c -d models -o <file> <url>` (direct Hugging Face resolve URLs, see [bench/README.md](bench/README.md)). The model id is the directory name (`qwen38-4bit`).

`strim serve` binds to 127.0.0.1 only and requires a bearer token, created on first start at `~/.strim/token` (mode 0600). Options: `--port N` (default 8203), `--token-file PATH`, `--no-auth` (loopback development only), `--max-inflight N`, `--max-background N`, `--no-admission`.

```sh
TOKEN="$(cat ~/.strim/token)"
curl -s http://127.0.0.1:8203/health

# OpenAI Chat Completions
curl -s http://127.0.0.1:8203/v1/chat/completions -H "Authorization: Bearer $TOKEN" -H 'content-type: application/json' \
  -d '{"model":"qwen38-4bit","messages":[{"role":"user","content":"hi"}],"max_tokens":32}'

# Anthropic Messages
curl -s http://127.0.0.1:8203/v1/messages -H "Authorization: Bearer $TOKEN" -H 'anthropic-version: 2023-06-01' -H 'content-type: application/json' \
  -d '{"model":"qwen38-4bit","max_tokens":32,"messages":[{"role":"user","content":"hi"}]}'

# OpenAI Responses
curl -s http://127.0.0.1:8203/v1/responses -H "Authorization: Bearer $TOKEN" -H 'content-type: application/json' \
  -d '{"model":"qwen38-4bit","input":"hi","max_output_tokens":32}'
```

### Claude Code

```sh
export ANTHROPIC_BASE_URL=http://127.0.0.1:8203
export ANTHROPIC_AUTH_TOKEN="$(cat ~/.strim/token)"
claude --model qwen38-4bit
```

Claude Code prints an `unrecognized_model` warning on stderr for the local id; requests are served normally.

### Codex (custom Responses provider)

```sh
export STRIM_SOAK_TOKEN="$(cat ~/.strim/token)"
codex exec --json --ephemeral --ignore-user-config --skip-git-repo-check -C "$PWD" -s workspace-write -m qwen38-4bit \
  -c 'model_provider="strim"' \
  -c 'model_providers.strim={name="strim", base_url="http://127.0.0.1:8203/v1", env_key="STRIM_SOAK_TOKEN", wire_api="responses"}' \
  -c 'approval_policy="never"' -- "your prompt"
```

Flags are `codexArgv` in [Sources/StrimSoak/SoakClients.swift](Sources/StrimSoak/SoakClients.swift). Send `x-strim-priority: background` to let interactive requests go first.

## Agent harness and MCP

`strim serve` hosts an MCP endpoint at `http://127.0.0.1:8203/mcp` with 4 tools: `strim_task`, `strim_job`, `strim_cancel`, `strim_ask`. A parent agent delegates a bounded task to the local model, which works in a sandboxed git-worktree job; the harness runs the required `verify` command itself and returns a summary and a patch for review.

```sh
strim mcp-config --claude     # prints the claude mcp add command
strim mcp-config --codex      # prints the codex mcp add command
strim jobs list               # jobs on disk, no server needed
```

See [docs/MCP.md](docs/MCP.md).

- **Evidence:** real Claude Code and Codex delegated through it: 4 of 4 runs passed their checks (n=1 per cell, trivial tasks). On a one-line fix the parent used 29.9K input tokens delegated vs 25.5K alone: no saving shown.
- Real-client soak, earlier build (2026-10-27, 30 minutes, `claude -p` and `codex exec` against `strim serve`, toy tasks): tasks passed 116 of 120, Claude Code 93.3%, Codex 100.0%, server crashes 0, HTTP 5xx 0. A reliability check, not a quality benchmark; the Claude Code failures were a harness allow-list flaw, since fixed. Not repeated on the current build or the current sandboxed harness.
- The agent benchmark has a corpus of 17 Swift and Go tasks. Its one committed run (120 runs, free arms, earlier corpus) is not quoted: part of it had an unusable test environment.

### Not yet validated

- A live soak with real Claude Code and Codex on the current build under the current sandboxed harness.
- The paid agent-benchmark pilot, so token savings from delegation are unproven.
- Multi-step agent quality of batched decode and the cache cuts against single-stream, and the agent benchmark on the current corpus.
- Other Mac memory tiers.

## How it works

- **MTP speculative decoding** with exact rollback of attention and linear-attention (GDN) state, adaptive depth (2-4), a 48k frequency-ranked draft vocabulary, and lossless speculative sampling.
- **Exact, chunk-aligned prefix cache:** a trie of 1,024-token chunks (KV, GDN state, MTP head state) with an LRU byte budget; a hit reproduces a miss bitwise. Assistant-start cuts and a footprint cap: 8-turn replay prefill 52.3 s before, 49.6 / 49.9 s after; per-cell peak footprint 27.0-32.6 GB vs 31.1-41.9 GB before. Already included in the head-to-head build.
- **Blocked GDN prefill kernel** (ported from rapid-mlx, Apache-2.0) and fused elementwise kernels.
- **Batched decode kernels:** batch-dimension GDN decode and conv Metal kernels cut the B=4 step from 49.5 to 42.3 ms (single-stream floor 34 ms); c=4 aggregate 57.4 to 63.3 tok/s and c=8 66.2 to 73.1 tok/s in a loaded sweep, already part of the head-to-head build (not additional).
- **Admission control:** interactive requests first, background capped one slot below the total (8 slots by default), bounded waiters with a deadline, memory-based refusal ([docs/ADMISSION.md](docs/ADMISSION.md)).
- **Token ledger:** per-conversation record of the exact token ids processed, so resent histories reuse the model's own tokens and the cache.
- **Sandboxed harness:** `sandbox-exec` jobs in isolated worktrees with a harness-run verify command.

Measured and rejected: in-batch MTP, a custom 4-bit prefill GEMM, batched prefill (see `docs/BATCH-MTP-2026-10-26.md`, `docs/PREFILL-SPIKE-2026-10-26.md`, `docs/BATCH-PREFILL-2026-10-26.md`).

## Security

Local, single-user, loopback only; not designed to be exposed to a network. Bearer token by default, Host and Origin checks, a separate control token, an untrusted-model design (sandboxed shell, contained file tools, isolated worktrees, SHA-256-approved patches).

Three reviews on 2026-10-28 (server surface, process launches and model-influenced code, release hygiene): the server review had 14 findings, 1 high; 6 are fixed and one partly. The process-launch review fixed 5 findings (credential directories refused as job working directories, sandbox temp-read denial, benchmark arms without a shell, token by environment reference).

Residuals: default job roots include any non-denied home directory; no per-route body limit; no wall-clock limit on a running generation; token-store hardening and permissive MCP token defaults are not reworked; the reviews were read-only (no live fuzzing, some sandbox fixes not executed under `sandbox-exec`); low and info items of the process-launch review were not addressed.

Report vulnerabilities through GitHub private vulnerability reporting (the repository's Security tab), see [SECURITY.md](SECURITY.md). Reviews: [server](docs/SECURITY-REVIEW-2026-10-28-server.md), [process launches](docs/SECURITY-REVIEW-2026-10-28-exec.md), [release hygiene](docs/SECURITY-REVIEW-2026-10-28-release.md).

## Limitations

- One model, one quantization, one machine class, one user. All measurements come from a single M5 Max, two passes with one rep each: treat differences of a few percent as noise.
- Not faster: cold prefill at 16K and 32K, aggregate throughput at c=4 and c=8, p95 first-token latency at 512-token concurrency.
- The prefix cache is in memory only. Speculative decoding and batching can differ from greedy at bf16 near-ties.
- The shipped `StrimApp` is a menu-bar shell over an older service and does not drive `strim serve`.

## Roadmap

- Qwen4 readiness (config-driven layer and head dimensions).
- Mixed quantization per memory tier, with a quality gate.
- GPU-index decode.
- Batched-matmul tuning for c=4 (the remaining aggregate-throughput gap).
- Cold-prefill kernels (the 2 to 3% gap at 16K and 32K).
- The paid agent-benchmark pilot.
- Menu-bar app and a disk-backed prefix cache, after that gate.

## Architecture

SwiftPM targets (`Package.swift`, MLX Swift 0.32.3):

| Target | Role |
|---|---|
| `StrimCore` | Model layers on MLX: quantized linear, attention, GDN (Metal kernels), caches, speculative stream |
| `StrimTokenizer` | Byte-level BPE tokenizer, HF-parity |
| `StrimTemplate` | Qwen3.8 chat-template renderer, ordered JSON, streaming tool-call parser |
| `StrimPrompt` | Token ledger, prompt builder, special-token-safe content spans |
| `StrimEngine` | Engine thread, scheduler, prefix cache, admission, batched decode, hot sessions |
| `StrimHTTP` | Loopback HTTP/1.1 server (SSE, Host/Origin checks, bearer auth, limits) |
| `StrimServer` | OpenAI chat, OpenAI Responses, Anthropic Messages adapters, session table, metrics |
| `StrimCLI` | `strim` command: `serve`, benches and gates |
| `StrimHarness` | Sandboxed worktree agent runner for the local model, `verify` gating |
| `StrimJobs` | Job queue and state machine over the harness |
| `StrimMCP` | MCP endpoint: `strim_task`, `strim_job`, `strim_cancel`, `strim_ask` |
| `StrimSoak`, `StrimAgentBench` | Real-client soak and agent benchmark drivers |
| `StrimSite` | This README and the results site generator |

## Reproduce

Hardware: Apple M5 Max, 64 GB, macOS 27.0.1. Versions: Strim 0.1.0 (2df65e7), rapid-mlx 0.15.7, mlx-vlm 0.7.10. One engine on the GPU at a time, in a foreground shell.

```sh
# head-to-head: OUTDIR [passes] [engines] [cell groups]; pass 2 runs the engines in reverse order
bench/h2h/run.sh bench/results/<dir> 1,2 strim,rapid-mlx,mlx-vlm g1,g2,g3
bench/h2h/summarize.sh bench/results/<dir>      # writes summary.md and results.json

# flags used
strim serve models/qwen38-4bit models/qwen38-mtp-4bit --port 8203 --no-auth
rapid-mlx --no-telemetry serve models/qwen38-4bit --port 8651 --max-num-seqs 4 --speculative-config '{"method":"mtp","model":"models/qwen38-mtp-4bit"}'
mlx_vlm.server --model models/qwen38-4bit --port 8651    # defaults: no MTP, no prefix cache

swift test --disable-sandbox                              # model-backed tests skip when models/ is absent
.build/release/strim checkprefix models/qwen38-4bit 4096 3 models/qwen38-mtp-4bit
.build/release/strim site check                           # every figure value occurs in its source file; links resolve
```

Details: [docs/BENCH.md](docs/BENCH.md), [bench/h2h/run.sh](bench/h2h/run.sh), [bench/soak/README.md](bench/soak/README.md).
